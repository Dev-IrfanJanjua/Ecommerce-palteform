# Catalog spec: shoes and variants

Contents: goals, types, generation approach, variant and stock rules, size systems, images, content rules, the 36 products, validation checklist.

The catalog is generated by code from a compact spec, not typed out as thousands of lines of JSON. The same spec will later become the MongoDB seed script, so the shape mirrors the future Mongoose models.

## Goals

- 6 collections, 36 products, each with color variants and sizes, so every UI state can be demonstrated: sale, new, low stock, sold-out size, sold-out color, fully sold-out product.
- Deterministic output: running the build twice gives identical data (use a seeded pseudo-random generator, never `Math.random()` unseeded).

## Types

```typescript
type Gender = "men" | "women" | "unisex";

interface ColorOption {
  name: string;            // "Off White"
  slug: string;            // "off-white"
  hex: string;             // swatch only (allowed hex, this is product data)
  images: string[];        // ordered, 4 per color, paths or placeholder keys
}

interface Variant {
  sku: string;             // `${BRAND}-${PRODUCTSLUG}-${COLORSLUG}-${SIZE}` uppercase
  colorSlug: string;
  size: string;            // EU size as string, e.g. "42"
  stock: number;           // integer >= 0
  priceCents?: number;     // optional override, omit unless needed
}

interface Product {
  id: string;              // stable, e.g. "prd_001"
  slug: string;
  name: string;
  collection: string;      // collection slug
  gender: Gender;
  shortDescription: string;   // one sentence
  description: string;        // two short paragraphs
  features: string[];         // 4 to 5 bullets
  material: string;
  care: string;
  priceCents: number;         // current selling price
  compareAtCents?: number;    // present only when on sale (original price)
  currency: string;           // from brand config
  colors: ColorOption[];
  sizes: string[];            // sizes offered for this product
  variants: Variant[];        // every color x size combination
  rating: number;             // 3.8 to 4.9, one decimal
  reviewCount: number;        // 5 to 420
  tags: string[];
  isNew: boolean;
  isBestseller: boolean;
  isFeatured: boolean;
  createdAt: string;          // ISO date; "new" items within the last 30 days, others older
}

interface Collection {
  slug: string;
  name: string;
  description: string;
  image: string;
  sortOrder: number;
}
```

## Generation approach

1. `src/data/catalog.source.ts` holds one compact entry per product: name, collection, gender, base price, color list (name and hex), size range, flags, and any special stock rule.
2. `src/data/catalog.ts` exports `buildCatalog()` that expands each entry into a full `Product` with variants, slugs, SKUs, generated copy, ratings, dates and stock, using a seeded generator.
3. A unit test (or a script) validates the output against the checklist at the end of this file.

## Variant and stock rules

- One variant per color x size. Sizes and colors are independent.
- Default stock per variant is a seeded integer from 0 to 40, tuned so that about 10 percent of variants have 0 stock and about 10 percent have 1 to 3 (low stock).
- Show low stock messaging when stock is 1 to 3 ("Only 2 left").
- Special rules (override the default):
  - **Tempo Racer** (12): every variant has stock 1 to 3.
  - **Trek Sandal** (28): one whole color has stock 0 in every size; the other color is normal.
  - **Aero Lite** (9): the two smallest and the largest size are out of stock in every color.
  - **Pool Clog** (30): fully sold out (all variants stock 0). The product page shows "Sold out", disables add to cart.
- A color is "available" if any of its variants has stock above 0; a size is "available" for a chosen color if that variant has stock above 0.

## Pricing rules

- Prices in the table below are in **USD as a placeholder**. Convert to the confirmed currency and round to a natural price point for that currency; store as integer minor units.
- Products flagged S (sale): `compareAtCents` is the table price, `priceCents` is about 20 percent lower, rounded to a natural price ending.
- All other products: `priceCents` is the table price, no `compareAtCents`.

## Size systems

Store sizes as EU numbers. If the user confirms US or both, derive display sizes from a `sizeChart` lookup (EU to US men's and women's), not by separate stock.

| Gender | EU sizes offered | Notes |
| --- | --- | --- |
| men | 40, 41, 42, 43, 44, 45, 46 | |
| women | 36, 37, 38, 39, 40, 41 | |
| unisex | 38, 39, 40, 41, 42, 43, 44, 45 | |

Sandals and slides use the same numeric sizes. Ask the user before adding half sizes or a kids range.

## Images

Real photos are not generated by the code. Image strategy comes from the user (placeholders, their own files, or downloaded stock). Whatever is chosen:

- Path convention: `/images/products/{slug}/{colorSlug}-{1..4}.webp`.
- One `ProductImage` component wraps `next/image`, uses token-based placeholder styling when a file is missing, and always sets `alt` as `{product name}, {color name}, view {n}`.
- Collection tile images: `/images/collections/{slug}.webp`. Hero images: `/images/hero/{name}.webp`.
- Aspect ratios: product card 4:5, gallery 4:5 (or 1:1 if the user prefers), hero 16:9 desktop and 4:5 mobile.

## Content rules for generated copy

- Product names here are original. Do not use real brand or trademarked model names.
- Short description: one sentence, benefit-led. Long description: two short paragraphs. Features: 4 to 5 bullets. Material and care text varies by collection (e.g., running: engineered mesh, EVA foam midsole, rubber outsole; boots: full-grain leather or suede, rubber lug sole; sandals: contoured footbed, rubber outsole).
- No exaggerated or unverifiable claims (no medical claims, no fake awards).
- Reviews: only the aggregate rating and count unless the user asks for a review list.

## Validation checklist (run after generating)

- 36 products, 6 collections, unique ids, slugs and SKUs.
- Every variant references an existing color; every product has colors x sizes variants.
- Sale products have `compareAtCents` greater than `priceCents`; others have none.
- Flag counts match the totals above.
- Special stock rules (products 9, 12, 28, 30) hold.
- About 10 percent of all variants are out of stock and about 10 percent low stock.
- `buildCatalog()` output is identical across two runs.
- No product contains a hard-coded currency symbol; formatting goes through `formatPrice()`.
